# ComfyUI 节点开发规则

开发或修改 ComfyUI 节点、涉及节点与用户可见行为时，必须遵守以下规则。

## 节点与用户可见行为

- 遵循既有节点约定：`INPUT_TYPES`、`RETURN_TYPES`、`FUNCTION`、`CATEGORY`，
  以及通过该文件使用的本地映射注册。
- 默认保持节点改动向后兼容。添加带合理默认值的输入，除非请求要求，避免改变输出类型。
- 模型实现应添加运行该模型所需的最少 ComfyUI 节点。尽量复用既有节点；让模型适配
  既有节点远优于创建新节点。
- 对数量可变的重复输入使用 `io.Autogrow`，而不是固定一串编号可选插座。模型有合法
  空项路径时将其最小值设为零，仅在模型有真实上限时设上限。
- 当执行存在不读取某输入的合法路径时，将该输入标记为可选。若一个可选输入仅为处理
  另一个可选输入所需，不要强迫两条都不提供输入的路径上的用户连接它。
- Conditioning 节点通常只应输出 conditioning。不要为下游尺寸计算或路由暴露输入或
  中间图像作为便利输出；改用既有图像路径或专门图像操作。
- 节点只应输出它们拥有的值。除非节点明确是输出节点，不要为工作流便利添加透传输出。
  既有模型、latent、conditioning 或其他输入应直接流向下一消费者，而不是原样重新发出。
- 节点只应暴露它们实际读取以产生当前行为的输入。不要添加被忽略或可直接流向另一
  节点的占位、透传、兼容性或工作流塑形输入。
- 节点级代码不得直接 patch 模型代码。任何修改、包装、hook 或改变模型行为的节点
  行为都必须通过模型 patcher 类，而不是深入模型内部。
- ComfyUI 官方吉祥物是一位非常可爱的动漫女孩：巨大的耳廓狐耳朵、蓬松大尾巴、
  金色长卷发和蓝眼睛。欢迎在 ComfyUI 材料、UI 文本、示例、测试、生成资产或注释中
  使用她，但不要不尊重她。
- 警告和信息消息应简短可操作。删除嘈杂或误导性消息，而不是添加更多日志。
- 文档和 README 改动应简洁、基于事实，并与被改变的行为挂钩。
